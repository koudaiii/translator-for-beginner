# 文法解説と英文添削 設計

## 目的
選択した、または入力した英文について、翻訳と同時に「文法解説」と「英文の添削」を表示し、英語を読みながら、また書きながら学べるようにする。利用者は作者本人のみ。

- **文法解説**: 直訳、文法ポイントと例文、単語・熟語。英文を読んで理解するため。
- **英文の添削**: 文法・語法の誤りとその理由、および用途別（チャット、メール、対面・通話、GitHub）の言い回し 4 つ。自分で英文を書くため。

## 前提
- Azure Translator では解説や添削を生成できないため、Azure OpenAI（Foundry）のモデルを使う。翻訳は引き続き Azure Translator で行う。
- リソース: サブスクリプション `sandbox`、リソースグループ `rg-translator-for-beginner`、リージョン `japaneast`、AIServices リソース `translator-for-beginner-foundry`（S0）。
- デプロイ: `gpt-6-luna`（2026-09-22、GlobalStandard、容量 10 = 10K TPM）。GPT-6 系で速く最も安いモデル。当初 `gpt-5-mini`（2025-08-07）で検証したが、世代が古いため切り替えた。
- API: Azure OpenAI v1 の Chat Completions（`POST https://translator-for-beginner-foundry.openai.azure.com/openai/v1/chat/completions`、ヘッダ `api-key`）。`api-version` は付けない。
- 認証はキー。Entra ID は使わない。
- GlobalStandard の容量（10K TPM）を超えて 429 になる場合は、クォータの範囲内でデプロイの容量を上げて対処する（従量課金のため、容量を上げても料金は変わらない）。
- 選択テキストと訳文は Microsoft のサーバーに送信される。
- 1 回の翻訳で Azure OpenAI を 4 回呼ぶ（直訳と単語、文法ポイント、直した箇所、言い回し）。検証では合計 2,000 トークン程度（入力込み）。

## 事前検証の結果（2026-10-09〜13）
- 解説 / `gpt-5-mini`（`reasoning_effort: "minimal"`）: スキーマどおりの JSON が返り、約 5 秒。最初のプロンプトでは `literal` が日本語にならず英文を区切っただけになり、固有名詞が単語一覧に入った。プロンプトの指示を具体化して解消した。
- 解説 / `gpt-6-luna`（`reasoning_effort: "none"`）: 約 2.7 秒と速いが、`examples` を空配列で返した。スキーマに `minItems` / `maxItems` を付け、プロンプトに「必ず 2 つ」と書いたところ、3 回とも例文 2 つずつが返った（約 4 秒、出力 470〜620 トークン）。Azure の strict モードは `minItems` / `maxItems` を受け付けた。
- 添削（1 回でまとめた版）/ `gpt-6-luna`: 約 1.5〜2 秒、出力 90〜190 トークン。用途の違いを抽象的に書いただけでは 4 つがほぼ同じ文になった。用途ごとに語調・長さ・言い回しの例を示すと、はっきり書き分けられた。誤りのある文では `corrections` に理由付きで 3 件、誤りのない文では空配列が返った。
- 並列実行（2026-10-13）: 翻訳、解説（和訳を渡さない版）、直した箇所、言い回しの 4 リクエストを同時に送った。翻訳 0.1〜0.5 秒、言い回し 1.4〜1.7 秒、直した箇所 1.7 秒、解説 3.1〜4.3 秒で、全体は解説の時間（3.5〜4.7 秒）で決まった。和訳を渡さなくても解説の品質は変わらなかった。添削を 2 つに分けると、各出力が 75〜100 トークンに減った。
- 解説の分割（2026-10-13）: 解説を「直訳と単語」と「文法ポイント」に分け、添削の 2 つと合わせて 4 リクエストを同時に 3 回送った。直訳と単語 1.3〜1.7 秒（出力約 90 トークン）、文法ポイント 2.6〜3.5 秒、直した箇所 1.2〜1.4 秒、言い回し 1.3〜1.7 秒。文法ポイント以外は 1.7 秒以内にそろう。

## 使い方
1. 入口はこれまでどおり 2 つ。ページ上で英文を選択して右クリックメニューか `Alt+T`（ページ上のポップアップ）、またはツールバーのポップアップに英文を入力（開いたときに選択中の文字があれば自動で入る）。
2. 翻訳を依頼する。完了は待たずに次へ進む。
3. 原文に日本語（ひらがな・カタカナ）が含まれず、Azure OpenAI が設定済みなら、翻訳と**同時に**次の 3 つを依頼する。
   - 直訳と単語（`reading`）
   - 文法ポイント（`grammar`）
   - 直した箇所（`corrections`）
   - 言い回し（`variants`）
4. 各ブロックにそれぞれ「翻訳中…」「直訳を作成中…」「文法を解説中…」「確認中…」「作成中…」を表示し、届いたものから順に中身に差し替える。互いの完了は待たない。
5. Azure OpenAI が未設定なら、翻訳だけを表示する（これまでと同じ見た目）。設定の有無は `aiAvailable` メッセージで最初に確認する（ストレージを読むだけなので数ミリ秒）。
6. 原文にひらがな・カタカナが含まれる場合は Azure OpenAI を呼ばない。翻訳の結果、検出言語が `ja` なら「すでに日本語です」を表示する（従来どおり）。ひらがな・カタカナを含まない日本語（漢字だけの短い文など）は Azure OpenAI に送られるが、許容する。

## 表示
上から次の順で並べる。
1. **訳文**
2. **文法解説**
   - 直訳（`reading` の結果）: `literal`
   - 単語・熟語（`reading` の結果）: `term` — `meaning`。空なら見出しごと出さない。
   - 文法ポイント（`grammar` の結果）: 各項目の見出し `point`、本文 `explanation`、例文（英文と、その下に小さく和訳）
3. **英文を直す**
   - 直した箇所（`corrections` の結果）: `before` → `after` と、その下に `reason`。空なら「文法の誤りは見つかりませんでした」。
   - 言い回し（`variants` の結果）: 「チャット」「メール」「対面・通話」「GitHub」のラベルと英文。それぞれに「コピー」ボタンを付け、`navigator.clipboard.writeText` でコピーし、押すと一時的に「コピーしました」と表示する。

セクションの間に区切り線を入れる。すべて `textContent` で組み立て、HTML として解釈させない。英文は `white-space: pre-wrap` で改行を保つ。ページ上のポップアップには最大の高さ（`max-height: 60vh` 程度）を設けて中をスクロールさせ、内容が増えるたびに位置を計算し直す。

## 構成の変更
- `manifest.json`: `host_permissions` に `https://*.openai.azure.com/*` を追加。バージョンを `0.6.0` に上げる。
- `options.html` / `options.js`: 「Azure OpenAI（解説・添削）」欄を追加し、`aoaiEndpoint`（例: `https://translator-for-beginner-foundry.openai.azure.com`）、`aoaiKey`、`aoaiDeployment`（既定値 `gpt-6-luna`）を `chrome.storage.local` に保存する。エンドポイントは末尾の `/` を除いて保存する。
- `background.js`:
  - `aiAvailable` メッセージで、Azure OpenAI の 3 項目がすべて設定済みかを真偽値で返す。キーそのものは返さない。
  - Azure OpenAI の呼び出しを `callAoai(schemaName, schema, system, user)` にまとめる。上限の判定、HTTP エラー、`finish_reason`、JSON の解析をここで扱う。
  - `reading`、`grammar`、`corrections`、`variants` の各メッセージ（いずれも `text` だけ）で、それぞれの JSON を返す。4 つは独立しており、service worker 内で並行に処理される（`onMessage` のハンドラは非同期で、互いを待たない）。
  - 送信元が自分の拡張機能でなければ応答しない（既存の `translate` と同じ）。
- `content.js`: 表示をセクション構成に変え、翻訳・直訳と単語・文法ポイント・直した箇所・言い回しの 5 つを同時に依頼し、届いたものから描画する。描画関数はこのファイル内に持つ（注入スクリプトのため）。
- `action.html` / `action.js`: 同じセクションと描画を追加する。描画関数は `action.js` 内に持つ。
- `popup.css`: セクション、ラベル、コピーボタン、最大の高さとスクロールのスタイルを追加する。

`content.js` と `action.js` に描画処理が重複する。共通化には注入ファイルの追加（`files: ['render.js', 'content.js']`）とポップアップでの読み込みが必要になる。実装時に重複が大きければ `render.js` に切り出す。目安は描画処理が合計 80 行を超えるかどうか。

## Azure OpenAI のリクエスト
共通の形:
```json
{
  "model": "<aoaiDeployment>",
  "reasoning_effort": "none",
  "messages": [
    { "role": "system", "content": "<システムプロンプト>" },
    { "role": "user", "content": "<ユーザー入力>" }
  ],
  "response_format": { "type": "json_schema", "json_schema": { "name": "<schemaName>", "strict": true, "schema": "<スキーマ>" } }
}
```
すべてのスキーマで、すべてのオブジェクトに `additionalProperties: false` と全プロパティの `required` を付ける（strict モードの要件）。件数は `minItems` / `maxItems` で指定する。

### 直訳と単語（`reading`）
ユーザー入力: `英文: <原文>`（翻訳を待たずに送るため、和訳は渡さない。以下の 3 つも同じく原文だけを渡す）

システムプロンプト（検証済み）:
```
あなたは英語初心者の日本人に教える英語教師です。与えられた英文について、日本語で簡潔に解説してください。
- literal: 英語の語順のまま、意味のまとまりごとに「 / 」で区切った日本語の直訳。英単語は書かない。例: 「私は / ずっと住んでいる / 東京に / 〜以来 / 私が / 卒業した / 大学を」
- vocabulary: 初心者がつまずきそうな単語・熟語を最大5個。固有名詞や中学1年レベルの基本語は入れない。meaning は文中での意味。
```

スキーマ:
```
{ literal: string, vocabulary: [{ term: string, meaning: string }] }  // vocabulary: 最大 5 件
```

### 文法ポイント（`grammar`）
ユーザー入力: `英文: <原文>`

システムプロンプト（検証済み）:
```
あなたは英語初心者の日本人に教える英語教師です。与えられた英文について、日本語で簡潔に解説してください。
- grammar: 文中の重要な文法項目を1〜3個。point は項目名、explanation は2〜3文の説明、examples には同じ文法を使った短い英文（en）と和訳（ja）を必ず2つ入れる。空にしない。
```

スキーマ:
```
{ grammar: [{ point: string, explanation: string, examples: [{ en: string, ja: string }] }] }  // grammar: 1〜3 件、examples: ちょうど 2 件
```

### 直した箇所（`corrections`）
ユーザー入力: `<原文>`

システムプロンプト（検証済み）:
```
あなたは英語初心者の日本人が書いた英文を直す英語の編集者です。入力の英文の文法・語法の誤りを1つずつ挙げる。before は元の表現、after は直した表現、reason は初心者向けの短い日本語の理由。誤りがなければ空配列にする（言い回しの好みは誤りに含めない）。
```

スキーマ:
```
{ corrections: [{ before: string, after: string, reason: string }] }  // 最大 5 件
```

### 言い回し（`variants`）
ユーザー入力: `<原文>`

システムプロンプト（検証済み）:
```
あなたは英語初心者の日本人が書いた英文を直す英語の編集者です。入力の英文の文法・語法の誤りを直し、意味を変えずに、次の4つの用途に合う英文をそれぞれ1つ書いてください。用途ごとに語調・長さ・言い回しをはっきり変え、同じ文を繰り返さない。情報を足したり削ったりしない。
- chat: Slack や Teams のチャット。短く、フレンドリーな口語。短縮形を使い、文を削ってよい（例: "Checked your PR — looks good!"）。挨拶や署名は付けない。
- email: 仕事のメール本文。完全な文で丁寧に。短縮形を避け、丁寧な定型表現を使う（例: "I apologize for the delayed response."）。入力に挨拶や署名がなければ付けない。
- spoken: 対面や通話で口に出して言う英語。言いやすい短い文に分け、自然なつなぎ言葉を使う（例: "So, ...", "Actually, ..."）。
- github: Issue や Pull Request のコメント。簡潔で明確、中立的な技術文。開発者の慣用表現を使ってよい（例: LGTM, repro）。コード・ファイル名・コマンドはバッククォートで囲む。
```

スキーマ:
```
{ chat: string, email: string, spoken: string, github: string }
```

直した箇所と言い回しは別々のモデル呼び出しなので、`corrections` の `after` と言い回しの英文が一致するとは限らない。直した箇所は「どこが誤りか」を学ぶため、言い回しは「そのまま使える文」を得るためと位置づけ、一致は求めない。

## 上限
原文が 1000 文字を超える場合は Azure OpenAI を呼ばず、直訳と単語・文法ポイント・直した箇所・言い回しの各ブロックに「解説・添削は 1000 文字までです。短く選択してください」と表示する。翻訳は従来どおり 5000 文字まで行う。判定は `background.js` の `callAoai` で行う。

## エラー処理
該当するセクションにメッセージを出す。ほかのセクションはそのまま残す。
- HTTP エラー: 「Azure OpenAI がエラーを返しました (<status>) <本文>」。401 はキー誤り、404 はデプロイ名かエンドポイントの誤り、429 はレート制限であることが本文から分かる。
- 通信失敗: 「通信に失敗しました: <message>」
- `finish_reason` が `stop` 以外、または JSON の解析失敗: 「結果を読み取れませんでした」
- 翻訳が失敗しても、ほかのブロックはそのまま表示する（互いに独立しているため）。

## セキュリティ
- Azure OpenAI のキーは `chrome.storage.local` に保存し、service worker の中だけで使う。`content.js`、`action.js`、ページには渡さない。
- LLM の出力は `textContent` で表示する。
- キーはコードやチャットに書かない。漏れた場合は Azure ポータルで再生成する。

## 対象外
解説・添削の履歴や単語帳の保存、ストリーミング表示、Entra ID 認証、Translator を使わず LLM だけで翻訳すること、解説の言語や詳しさの切り替え、日本語から英文を作ること、選択範囲や入力欄の文字を直した文で置き換えること、言い回しの和訳、解説・添削の自動実行のオン・オフ切り替え。

## テスト（手動）
- 設定ページで Azure OpenAI の 3 項目を保存し、英文 1 文を選択して実行すると、訳文・文法解説・英文を直すの 3 セクションが出る。
- 直訳が日本語で、` / ` 区切りになっている。文法ポイントごとに例文が 2 つある。
- 誤りを含む英文（例: `I want to know about the reason of this error, because I can not reproduce it in my local.`）で、直した箇所が理由付きで出て、4 つの言い回しが用途ごとに違う。
- 誤りのない英文で「文法の誤りは見つかりませんでした」と出る。
- 各「コピー」ボタンでクリップボードに入る（ページ上とツールバーの両方）。
- Azure OpenAI 未設定では、翻訳だけが表示される。
- 日本語の文では「すでに日本語です」だけが表示される。
- 誤ったキーで 401、誤ったデプロイ名で 404 のメッセージが AI を使う 4 つのブロックに出て、訳文は残る。
- 訳文がまず出て、直訳と単語・直した箇所・言い回しが続き、最後に文法ポイントが出る（届いた順に表示される）。
- 1000 文字を超え 5000 文字以下の選択で、翻訳は出て、解説と添削に上限のメッセージが出る。
- 長い内容でもポップアップが画面からはみ出さず、中をスクロールできる。
- ツールバーのポップアップで入力した英文でも同じように動く。
- 表示中にページをクリックするか Esc を押すと、ページ上のポップアップが閉じる。
